# Engineering Gates — the live-enforcement registry

> **What this is:** the single honest map from every engineering quality domain (and each of the 12 architecture principles) to its LIVE enforcement: the CI job, lint rule, drift-guard test, or mandatory review checklist that makes it real. Where a claim maps to nothing, the row says **UNENFORCED**, with a disposition. The purpose: nothing in our standards is "just documentation" — it is either enforced, or its gap is visible and owned.
> **Scope:** this registry maps the **`apps/web`** app (the live site). The `apps/sandbox` work-front (uncommitted WIP) has its own eslint/vitest/tsconfig and is governed by `docs/sandbox-app/SANDBOX_RULES.md` + its gated per-slice battery — it is deliberately NOT yet wired into the web CI page-lists (pa11y/Lighthouse) or `--filter`ed into `ci.yml`; full CI wiring is a promotion-to-public gate in `docs/sandbox-app/BUILD_ORDER.md`.
> **Sibling systems:** the content gates live in `docs/tech/ux-governance/` (CI-guarded by `validate:ux-canon`); process playbooks in `docs/playbooks/` (local); the recurring/scheduled jobs (crons + timed workflows) are cataloged in `docs/tech/infrastructure.md` §8 → _Scheduled jobs — every cadence in one place_. This file is git-tracked and audited whenever CI composition changes.
> **Last full audit:** 2026-07-17 (workflows, validators, lint config, coverage config, audit-tool configs all read at source).

## Change discipline

Adding a quality claim to CLAUDE.md or the standards? Add its enforcement row here in the same PR — or an UNENFORCED row with a disposition. CI composition changes (workflows, validators, lint promotions) update this file in the same PR. The registry is audited (all rows re-verified at source) whenever a domain's tooling changes.

**Weekly `/market` refresh write-path gates (2026-08-11, B-wave):** the automated weekly PR (`market-refresh-weekly.yml`) is gated in-workflow BEFORE the PR opens — `generate.mjs --check` (drift, incl. the data_status panel), jargon gate, full market vitest (incl. the panel golden test), and a scoped prettier check on every pipeline-written file — AND the PR itself now triggers the full `pull_request` CI battery via the `MARKET_REFRESH_PR_TOKEN` fine-grained PAT (`|| github.token` fallback if the secret is removed; an expired token fails the PR step loudly). Editorial overrides are cycle-scoped (`_cycle` stamp) so stale judgment cannot silently pin onto a new cycle.

**Weekly `/market` DATA-HONESTY gates (2026-08-24, remediation of the founder-ordered audit — PENDING_ALL 5.127/5.128/5.134a):** the write-path gates above reconcile SCORES, POINTS and generated COPY.
